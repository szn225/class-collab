# 2.5.3 页面响应优化测试版

日期：2026-11-13。仅改小程序客户端，本轮未部署后端、迁移区域或修改数据库结构；未提审或正式发布。

## 改动

- 活动详情与素材改为两个并行读取，去掉原来的重复详情读取（三次串行）。打开时先展示活动列表已有的概要。
- 用户信息与活动列表并行加载。
- 只读切页与写操作锁分离，切页先显示已有内容再刷新；返回页面不会因读请求锁住操作。
- 只合并相同环境、会话、参数下尚未完成的只读请求，不保留已完成结果；写请求使共享读取失效。报价、扣点、权限仍走现有服务端验证。
- 账号、活动、页面切换和离开页面后，丢弃旧页面读取结果，避免快速切页时内容串用。素材轮询也检查作用域。
- 成绩页先展示本地记录，再后台同步；同账号同学生 15 秒内干净数据的重复进页不重复拉取，存在待保存变更则继续同步。隐藏页面不再触发无变更的同步。
- 云端数据变化后只更新仍在当前账号和学生下的可见页面，保留原有冲突、重试和草稿处理。

## 验证

- 4 组性能与时序测试通过：并行请求、请求合并、写后读取失效、失败重试、快速切页、旧响应隔离、后台成绩同步。
- 原有 backend test 的 35 项通过，包含权限、生成、AI 排版、扣点与小程序流程。
- 成绩本地 PostgreSQL 集成 17 项通过，游客保存检查通过，小程序 TypeScript 检查通过。
- 微信模拟器资料、文章、管理页渲染与结束加载检查通过，截图为静态隔离接口测试；不代表真机网络计时。
- 原生预览二维码为 phone-preview.png，最终包路径 /private/tmp/hui-miniprogram-2.5.3-bgv9Ka；包清单见 manifest.json。

诊断中的单接口 2～3 秒仍是旧服务的探测结果，本轮没有宣称降低这一服务端基础延迟。按原样本估算，活动读取链路由三次累计约 6.6 秒变为等待较慢的一个并行请求；真实手机速度需扫码验证。后端分段计时、区域对比、按范围查询仍待后续实施。

模拟器曾尝试动态慢请求拦截但未可靠完成，最终原生验收使用静态响应；慢请求、竞态的断言以本地可控延迟测试为依据。未调用真实付费模型、未测试生产写入。
