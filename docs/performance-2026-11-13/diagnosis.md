# 小程序页面等待诊断

检查日期：2026-11-13。仅进行只读代码检查、现网接口与数据库探测，没有修改线上服务或业务数据。

## 实测

样本来自代理运行环境，不代表用户手机网络，不是生产 P95。原始结果见 latency.json。

| 操作 | 总耗时 |
| --- | --- |
| me，3 次 | 2.04–2.63 秒 |
| activities.list | 2.81 秒 |
| activity.get | 2.09 秒 |
| materials.list | 2.40 秒 |
| article.get | 2.80 秒 |
| grades.students.list | 2.63 秒 |
| 直接读取 hui_read，2 次 | 0.16–0.37 秒 |

接口响应内容仅几十字节至约 5 KB，等待首字节占主要部分，并非文章下载体积导致。所有业务探测均为 HTTP 200。

## 已确认的等待链路

1. `miniprogram/pages/co-create/index.js` 的 openActivity 先调用 activity.get，再进入 loadStream；loadStream 又调用 activity.get，最后调用 materials.list。三次串行请求中有一次重复。按本次单接口样本相加约 6.6 秒；这是链路估算，尚未在手机逐次点击计时。
2. restore 先 me 再 activities.list；settings 在 activity.get 返回后才切屏；goBack 会 refresh。缺少已有数据即时展示与后台更新，网络时间直接变为切页等待。
3. 当前及上一个生产部署的函数区域均为 iad1。响应头为 sin1::iad1，请求经新加坡入口进入美国函数。这不是最近一版新增的区域变化。跨区是需验证的延迟因素；尚无函数内部时序，不能把全部耗时归于区域或冷启动。
4. backend/src/lib/v2/store.ts 每次 readState 读取整份共享状态，现有响应约 184 KB。当前规模尚小，但用户、任务、活动历史增长后会放大读取与解析开销。读接口缺少按用户、按活动的数据库查询。
5. 成绩模块 gradePage 在已开启云同步时，先 await sync 再执行原页面 onShow；即使无本地修改，也会 workspace.get。后端每个 grades 请求先 hui_read 鉴权，再 hui_grades，形成额外串行读取。主入口 home 的本地刷新不属于同一云请求链路。

## 优先优化顺序

1. 去除活动详情重复请求，合并或并行独立读取；页面先展示已有数据，后台更新。权限变化、切换账号、请求过期结果必须正确隔离。
2. 减少返回和重复进入页面时不必要的刷新；成绩页优先显示本地数据，保留同步冲突与账号隔离处理。
3. 增加鉴权、数据库、图片签名的分段耗时，再确认数据库真实区域，用区域预览部署做对比。不要未经验证就迁移生产区域。
4. 逐步改为按范围读取数据，避免每个接口读取全部共享状态。余额、权限和扣点不可用随意缓存替代实时校验。

本轮结论：现网单接口延迟与客户端串行/重复等待叠加，是已复现的主要问题。尚未完成手机端网络分析、服务端分段计时或性能修复。
