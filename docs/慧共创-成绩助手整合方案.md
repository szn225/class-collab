# 慧共创 · 成绩助手整合方案

> 最新交互以 2.1.1 真机反馈修订为准：首页仅保留两个入口，无示例或宣传区；成绩直接填写，点击保存时登录，取消登录保留表单，成功后明确显示保存结果。下文包含原整合架构及早期体验方案的设计记录。

日期：2026-11-09。状态：整合设计已形成首版本地实现；实施说明与验证方式见《慧共创-成绩助手开发与验收》。

## 1. 整合目标

保留慧共创作为唯一发布的小程序，把成绩助手迁入其中，形成一个应用、一个账号、两个业务模块。不是从慧共创跳转打开原独立小程序。

既定体验：双入口首页无需登录；活动共创可浏览演示，参与时登录；成绩可在游客状态下真实录入和本机保存，主动开启云端保存时再登录。一个账号支持多个学生档案。

## 2. 代码现状与结论

| 项目 | 代码现状 | 整合决定 |
| --- | --- | --- |
| 慧共创入口 | `miniprogram/app.json` 仅注册 `pages/co-create/index`；该页默认显示登录界面 | 新增公共首页，保留现有共创业务页，调整其游客入口 |
| 慧共创身份 | `backend/src/lib/v2/identity.ts` 验证微信 code；`domain.ts` 建立用户与会话 | 复用现有 userId 和登录接口，不新建成绩账号 |
| 全局登录 | `app.js` 管理 `hui.session`、`hui.user`；`utils/v2.js` 携带会话并处理 401 | 抽取统一登录入口、登录后返回和状态通知，两个模块共同使用 |
| 成绩助手 | 原生 TypeScript；6 个页面；core、services、datasource 已分层 | 迁移页面与业务逻辑，保留计算内核和既有验证用例 |
| 成绩存储 | `LocalDataSource` 管理考试；其他服务和页面直接读写计划、草稿、设置等 | 先统一存储访问，再引入账号和学生作用域 |
| 原成绩导航 | 应用级 custom-tab-bar 与大量 `wx.switchTab` | 改为成绩模块内部导航，统一重写路由，不直接复制原 app.json |
| 后端存储 | 当前 v2 使用 Supabase RPC 对聚合状态进行 CAS 更新 | 复用后端部署和认证，成绩使用独立表，避免全量成绩挤入共创聚合状态 |

## 3. 应用组织

建议主包承载公共首页、统一账号页和现有共创入口；成绩页面放入 `packages/grades/` 普通分包，保留定位、录入、复盘、参照、考试详情和模块设置。

应用仅保留慧共创的 App 注册、AppID、环境配置和会话管理。成绩助手的 App 初始化改为模块初始化，在进入模块时加载参照数据，不再单独注册 App。

将成绩的 core、services、datasource、数据集、样式和专属组件尽量放在成绩包内部。公共依赖的位置、TypeScript 编译和依赖构建方式在迁移验证时确定，以实际编译、包体和真机结果为准。慧共创当前未启用 TypeScript 编译插件，需要在整合配置时补齐并验证 JS/TS 共存。

成绩原有的四个导航项改为模块内部组件，不占用整个应用的全局 TabBar；所有旧路径与 switchTab 调用统一替换。进入成绩后提供“返回慧共创”入口。统一账号页管理登录、退出和账号资料；成绩模块设置页仅保留学生、参照口径和备份等业务设置。

样式优先限定在成绩页面和组件内，避免把成绩 app.wxss 整体覆盖到慧共创。

## 4. 身份与数据归属

关系：用户 userId → 多个学生 studentId → 考试记录、复盘计划、目标学校及学生设置。活动成员权限继续独立管理，与学生档案不建立隐式授权关系。

服务端以已有会话认证出的 userId 为准，不信任客户端传入的 ownerUserId。学生查询及任何考试、计划操作都必须核验当前用户对该学生的所有权。共创成员、协作者和现有活动管理接口不获得成绩访问能力。

建议新增学生、考试、复盘计划和导入批次表。保留考试现有 dataVersion、derivedSnapshot，历史记录不得因换参照口径被无提示重算。导入批次及记录来源标识建立唯一约束，用于重试去重。数据库迁移以增量 SQL 交付，不覆盖现有用户和活动。

用户登录和云端同步是两个状态：在共创模块登录，不代表允许自动上传此前的游客成绩。成绩模块需单独展示“仅本机 / 已开启同步 / 待同步 / 同步失败”等状态。

## 5. 本机存储先行改造

新增统一的成绩存储作用域，区分游客身份、登录账号与学生档案；示例数据使用独立的只读数据源。示意键空间：

```text
hui.grades.guest.<guestId>.student.<studentId>.*
hui.grades.user.<userId>.student.<studentId>.*
```

必须纳入作用域的内容：考试、复盘计划、学生资料、录入草稿、目标学校、考试标记以及个性化学校设置。参照数据集可按版本共享，个人使用的口径指针需明确归属。备份导入导出也只能操作当前选定作用域。

需要改造的直接存储调用已发现于：`plan.service.ts`、`dataset.service.ts`、`record.service.ts`、`target-school.service.ts`、`exam-detail/index.ts`，不能只替换 `services/data-source.ts`。

切换账号、退出、会话过期或切换学生时，重新绑定数据源，失效页面缓存并清空私有展示；旧异步请求返回时核验作用域，禁止写入当前新账号/学生。已有账号的缓存保留在其专属空间，退出不转成游客数据。

## 6. 游客记录与旧独立小程序迁移

游客导入：用户主动登录后，选择目标学生，查看本机待导入记录数量并确认。拒绝导入可继续保留游客本机记录；不得自动合并到当前学生。

导入使用稳定来源标识和批次 ID；网络中断可重试，服务端事务保证批次一致性，完成后显示成功数量并保留本机备份。ID 冲突而内容不同的记录不得静默覆盖。复盘计划引用的考试 ID 随迁移映射保持关联。

原独立小程序与慧共创的 project.config.json 配置了不同 AppID，不能把文件夹搬入视为数据迁移完成，也不能假设原身份或原本机存储已可直接复用。已有成绩的交付路径采用原助手已具备的 JSON 备份导出，再由整合版选择目标学生导入；不按昵称或学校猜测账号归属。实施时核对备份字段覆盖范围，遗漏的草稿或偏好明确说明。

## 7. 云端同步范围

第一版采用本机优先：先本机可靠保存，用户开启云端同步后再提交账号下的改动；断网显示待同步，恢复后可重试。未开启云端同步时仍可完整使用本机功能。

每条云端可修改数据带 revision；更新和删除校验 revision，冲突保留双方版本并由用户选择，禁止简单按最后写入覆盖。删除使用可同步的删除标记，防止离线设备将已删除数据恢复。参照口径的版本与考试快照随记录保留。

## 8. 实施顺序与验收

1. 迁移成绩业务包、路由与样式，接入慧共创单一 App 生命周期；先验证原成绩录入、计算、趋势、复盘和备份仍可本机使用。
2. 建立公共首页和统一登录入口，打通登录后返回与两个模块状态刷新；登录取消后仍可浏览。共创显示姓名要求仅作用于需要该资料的业务操作，不作为成绩体验前置条件。
3. 完成游客/账号/多学生存储作用域和切换保护；覆盖草稿、计划、标记和备份，验证无跨账号残留。
4. 增加成绩独立表和授权接口，完成主动开启同步、游客导入、重复请求去重、离线重试和冲突处理。
5. 回归共创创建、加入、上传、生成文章，以及旧成绩 JSON 迁移；在微信开发者工具及真机检查导航、编译、包体与冷启动体验。

关键验收：游客真实录入可保存；任何模块登录后共享身份；登录不自动上传游客成绩；多学生互不混用；A 账号退出后 B 账号无法看到或修改 A 的任何成绩、草稿和计划；导入重试不重复；原共创权限和文章流程继续有效。

本文件记录整合设计。首版本地实现与验证范围见《慧共创-成绩助手开发与验收》；上线数据库迁移、后端部署与小程序发布仍需单独执行。
