## 本轮确认：终端与界面调整（2026-11-05）

以下调整优先于文档中组织者 Web 工作台的原有描述：

- 活动发起人及协作者在手机端完成活动管理、素材选材、AI 生成、文章编辑和定稿，取消组织者电脑工作台。
- 电脑端保留文章链接预览、复制正文及分享；用户自行将正文粘贴到公众号后台发布，也可以直接将文章链接分享给其他人阅读。公开分享继续遵循可撤销分享凭证与权限规则。
- 平台管理员使用独立 Web 后台管理用户、点数、预算与审计。
- 界面保持整洁简约，删除无必要英文、宣传介绍和装饰内容，保留状态、费用、权限及异常等必要提示。
- 当前仅制作交互 UI 原型，待用户确认后再开展正式前后端开发。
- 手机端交互稿覆盖登录至完整功能流程，以及发起人、协作者和参与者界面。创建/编辑表单仅保留必填活动名称与选填活动说明，不额外增加活动属性；公告、成员权限、收集状态作为必要管理操作保留。

## 1. 产品概述

慧共创是一款面向小团队的活动资料共创与公众号成文工具。组织者创建一次活动，邀请参与者在类似群聊的资料窗口中提交文字和照片，组织者可人工筛选素材，也可交由 AI 自动整理，最终生成、修改和导出公众号文章。

适用场景包括班级活动、社团活动、志愿服务、公司团建及其他小团队活动。不要求用户先建立长期团队或维护组织架构。

产品主流程：

> 创建活动 → 分享邀请 → 参与者提交资料 → 人工或 AI 选材 → AI 生成草稿 → 编辑定稿 → 导出至公众号。

资料窗口采用群聊式呈现，但不提供消息回复、私聊、语音通话等社交功能。

## 2. 目标与成功标准

### 2.1 产品目标

- 降低参与者提交资料的成本，使其像发送文字和照片一样完成贡献。
- 将分散资料与活动事实关联，帮助组织者得到内容准确、可编辑的文章草稿。
- 正确识别用户与活动权限，解决同名串号和全局管理员角色不合理的问题。
- 通过点数、调用限额和预算控制，使 AI 成本可管理、可追溯。
- 为运营者提供独立 Web 后台，手动管理用户点数及异常使用。

### 2.2 上线后观察指标

记录创建活动数、受邀进入至首次提交的转化、有效素材数、生成成功率、草稿至定稿转化、每篇文章的 AI 成本、退款率、异常调用拦截量。首版不预设未经验证的业务增长目标；具体目标待试用数据形成后确定。

## 4. 用户角色与权限

### 4.1 角色定义

| 角色 | 权限范围 |
|---|---|
| 平台管理员 | 使用独立 Web 后台，管理用户点数、规则、风险和平台运行；不由普通用户自动获得 |
| 活动发起人 | 管理自己创建的活动、邀请、协作者、素材、文章和该活动的 AI 使用授权 |
| 活动协作者 | 在被授权的活动中整理素材、编辑文章；使用 AI 需发起人明确授权 |
| 活动参与者 | 查看所属活动的资料流和对成员开放的文章，提交与撤回自己的资料 |

活动发起人同时也是参与者。同一用户在不同活动中角色可以不同。平台管理员不是所有活动的默认业务协作者。

### 4.2 权限规则

- 创建活动者成为该活动发起人，不要求其具有全局管理员身份。
- 发起人可添加或移除共同管理的协作者，首版不支持活动所有权转移。
- 协作者默认没有消费发起人点数的权限；发起人可授予、撤销，授权范围在界面明确显示。
- AI 操作均消耗活动发起人的点数，发起人退出设备不影响账户归属。
- 普通参与者不能调用活动 AI、修改活动状态、管理他人资料或调整点数。
- 发起人不可被普通移除成员操作移除；移除成员不自动删除其历史素材。
- 每个读写接口都校验真实身份、成员关系和对应操作权限，不信任客户端传入的 userId 或角色。
- 资料流默认仅对活动成员开放。公开分享文章须通过明确的分享操作，不能以知道活动 ID 作为访问凭据。

## 5. 用户身份与旧数据迁移

### 5.1 新用户与老用户识别

- 小程序采用微信登录流程，由服务端取得并绑定用户标识；姓名不作为唯一身份凭据。
- OpenID 作为本小程序范围内的微信身份关联键，不直接暴露给其他成员。
- 首次识别创建用户，填写显示姓名；再次进入恢复原用户、点数、活动与角色。
- 允许同名，提供修改显示姓名能力；活动中可提示重名并建议补充称呼，不阻止使用。
- 不为识别身份额外索取手机号、微信头像或微信昵称。
- 登录失败可重试，不能降级为按姓名进入已有账号。服务端签发会话，校验过期和撤销状态。

### 5.2 旧用户迁移

- 不允许仅凭同名自动认领历史用户，尤其是旧管理员。
- 上线前备份用户、素材、成员关系、活动及文章数据。
- 平台管理员核对后将历史账户绑定至新身份；每个旧账号只能完成一次明确绑定，操作留痕。
- 无法确认归属的旧账号保留为待认领记录，不开放其管理权限；历史素材保留原作者展示信息。
- 旧全局管理员角色不自动授予平台后台权限。历史活动创建者经核对后映射为发起人。
- 迁移账户是否获得新用户赠点由独立规则控制，禁止通过解绑、删除重建重复领取。

## 6. 信息架构与终端分工

### 6.1 小程序

- 共创活动：参与或管理的活动、筛选、创建活动、邀请码加入。
- 活动资料窗口：公告、成员入口、资料流、文字图片输入、管理入口。
- 活动管理：基本信息、成员及协作者、收集状态、素材选材、文章入口。
- 文章：生成确认、任务状态、预览、编辑、版本、定稿、导出。
- 我的：显示姓名、点数余额、点数明细、使用说明。

### 6.2 Web

提供两种明确隔离的权限空间：

- 平台管理后台：只向平台管理员开放，完成用户、点数、调用、预算及风险管理。
- 组织者工作台：用户只能查看自己有权限的活动，方便电脑端筛选图片、编辑文章和复制正文，不得进入平台管理区域。

建议采用小程序确认的一次性网页登录凭证，使普通用户无需新增密码；平台后台采用单独的管理员登录与会话机制。具体认证方案在技术设计中确定，但不得通过输入姓名登录后台，也不得在链接中长期传递用户身份凭据。

## 7. 活动管理需求

### 7.1 创建与编辑

必填活动名称；选填活动说明、时间、地点、关键环节及素材要求。创建后生成活动 ID 和邀请码，默认开始收集。

创建活动免费，但设每用户活动数量及创建频率上限，避免滥建。创建活动页面明确“创建和收集免费，AI 处理消耗点数”。点数为零仍可按限额创建、收集和编辑，不可启动付费 AI 任务。

发起人及有权限的协作者可以编辑活动事实。已经用于文章的活动信息发生变化时，提示草稿可能需要更新。

### 7.2 邀请与进入

- 支持分享卡片、二维码和六位邀请码。
- 新用户从邀请进入时，完成身份识别和姓名填写后回到目标活动，不丢失邀请上下文。
- 已加入成员直接进入；未加入者先展示名称、说明及收集状态，再确认加入。
- 错误、失效或被撤销的邀请须明确提示。发起人可重置邀请，使旧邀请失效，已有成员不受影响。
- 暂停收集的活动仍可允许受邀者加入并查看，但明确提示不能提交；归档活动默认不接受新成员。

### 7.3 成员管理

展示姓名、活动角色和加入时间；发起人可移除参与者、管理协作者。被移除成员停止访问该活动和发起新操作，历史资料保留并可由发起人排除。邀请码重置与成员移除分别生效，防止被移除者直接使用原邀请重新加入。

## 8. 群聊式资料窗口

### 8.1 展示与交互

- 按时间顺序展示发送者、时间、文字、单图或多图卡片；向上加载历史，新资料出现时更新。
- 用户在查看历史时不强制跳到底部，以“有新资料”提示返回最新位置。
- 顶部显示活动名称、收集状态、公告和文章入口；管理按钮按角色展示。
- 不提供回复、评论、私聊、通话、语音上传、已读回执或消息转发。

### 8.2 发送资料

- 支持纯文字、纯图片、多图附说明；图片与说明作为同一份资料关联保存。
- 选图后进入待发送区域，可预览、移除、补说明；点击发送后再上传提交。
- 上传显示进度和失败原因，失败保留输入与待发送图片，支持重试。
- 同一次发送重复点击或网络重试不得产生重复资料。部分图片上传失败时明确展示结果，不重复提交已成功部分。
- 当前每次最多 6 张、单图最大 10 MB 可作为初始建议值，最终限额见参数表；服务端与客户端一致校验。
- 同步等待时间和历史加载使用明确的加载、空状态和错误重试提示。

### 8.3 撤回

- 用户可以撤回自己已发送的资料，首版不设置聊天软件式的短时限；归档后需要先由发起人恢复活动才能撤回。
- 撤回前确认，撤回后资料不再显示正文和图片，可保留“该资料已撤回”占位。
- 被撤回资料不进入后续 AI 任务和选材列表；文件、识图缓存按清理策略处理。
- 已用于文章版本的资料被撤回时，给管理者显示受影响版本提醒，不静默修改已有文章。
- 正在生成时撤回，任务基于已确认快照运行；结果须标记素材发生变化，不能无提示直接定稿。
- 已经复制或发布到外部公众号的内容无法由本系统自动撤回，界面说明需人工核对外部文章。

## 9. 素材整理与选材

每份有效资料具有独立的人工选择状态：

| 状态 | 默认规则 |
|---|---|
| 自动选择 | 默认值，AI 判断采用与否，可去重、筛选 |
| 指定采用 | 必须纳入本次草稿的依据，允许合并改写；指定图片应安排入文 |
| 指定排除 | 不传入本次内容生成与识图任务，不采用已有识别结果作为依据 |

管理者可筛选提交人、类型、时间和选材状态，支持批量设置。无需人工处理所有素材。

生成模式有两种：

1. 智能选材：使用指定采用内容，并从自动选择内容中筛选；排除项不参与。
2. 仅用指定素材：仅采用人工指定项，无指定内容时不能发起任务。

生成前展示文字数、图片数、待识图数和预计扣点。指定素材超出单次限额时要求用户调整，不得静默丢弃。生成后提供采用素材列表与未采用原因摘要，方便核对，不展示模型内部推理。

## 10. AI 识图与文章生成

### 10.1 输入与事实约束

- 输入包括活动名称、时间地点、说明、关键环节、有效文字、图片说明及识图结果。
- 图片理解识别可见内容、场景和相似图片，辅助选材；不得根据照片猜测人名、身份或无法确认的事实。
- 人工填写的活动事实优先于模型推断。信息冲突或事实不足时提示补充，不凭空编造时间、人数、引语、奖项或具体事件。
- 不再对所有活动强制生成固定长文；生成前选择或填写篇幅、语气和重点，提供默认值。
- AI 只在用户确认任务后调用，上传图片、打开页面、查看素材均不自动产生付费调用。

### 10.2 识图与生成过程

一次“生成草稿”可包含必要的识图和写作阶段，确认页显示合并预计费用。若以后提供独立“重新识图”操作，也必须单独确认费用。

同一有效图片未变化时复用识图结果；图片内容、识别模型或必要处理版本变化时才能重新识别。缓存不得造成不同用户或无权限活动之间的数据泄露。

识图失败时展示失败图片，允许重试或取消任务；不得静默忽略指定采用图片并宣布完整成功。未产生完整草稿的任务按退款规则处理。

### 10.3 任务体验

- 任务异步运行，状态包括排队、识图、生成、成功、失败、待核实。
- 用户离开页面或重新打开仍能查看进度；不能把前端超时等同于服务端任务失败。
- 同一活动同时最多一个 AI 任务，重复请求返回原任务。
- 生成基于固定素材快照，保存输入版本；期间新增、撤回或修改资料均提示结果可能未覆盖最新内容。
- 模型服务异常给出可理解的提示，不向用户暴露密钥、原始服务错误或内部提示词。

## 11. 文章编辑、版本与导出

- AI 输出为草稿，不直接代表发布，也不改变活动收集状态。
- 管理者可以修改标题、正文、图片顺序和图片说明，预览公众号排版。
- 编辑支持保存状态提示，离开前提示未保存修改；多人编辑至少提供版本冲突检测，防止覆盖。
- 重新生成需再次扣点确认，创建新版本，保留旧版本和人工修改，不静默覆盖。
- 可以查看、恢复历史版本；首版不要求复杂差异比较。
- 定稿为人工确认动作，有未解决的素材变更提醒时须先确认核对。
- 导出提供电脑预览、复制正文和操作指引；保持现有公众号复制能力，并验证标题、图片与段落排版。
- 系统不自动发布公众号。可由管理者手动标记“已发布”并填写外部链接，该状态仅表示人工记录。
- 文章默认活动内可见；公开预览通过可撤销分享凭证访问。旧的仅凭活动 ID 公开访问方式需迁移或关闭。

## 12. 状态设计

### 12.1 活动收集状态

| 状态 | 允许行为 |
|---|---|
| 收集中 | 按权限加入、提交、撤回、整理与生成 |
| 暂停收集 | 可查看、整理、撤回与生成；禁止新增提交，可恢复收集 |
| 已归档 | 只读保留资料和文章；禁止新成员、新提交和 AI 任务，发起人可恢复 |

前端、上传凭证、素材写入接口均执行状态检查；文件上传完成但资料提交时活动已暂停，应明确失败并回收孤立文件。

### 12.2 文章状态

文章独立记录未生成、草稿、已定稿，以及可选人工标记的已发布。新增草稿不删除原定稿；新草稿定稿后更新当前版本指针。收集中也可生成草稿，已定稿也可继续收集并提示待更新。

## 13. 点数账户与计费规则

### 13.1 账户与赠点

- 每个用户一个点数账户，使用整数点数；展示可用点数、冻结点数和变动明细。
- 新用户赠点一次，金额可配置，必须有唯一发放记录。
- 点数不能转赠、提现或通过小程序支付购买；用户不足时显示联系运营者申请补充的说明，不出现虚假充值入口。
- 平台管理员手动增减点数，必须记录原因、操作者、时间、变更前后余额和关联单号。
- 点数不得为负，不能扣除已冻结给在途任务的额度；停用账户不抹除余额与账本。

### 13.2 计费对象

| 行为 | 扣点 |
|---|---|
| 创建活动、加入、上传、撤回、浏览、人工选材 | 不扣点，受容量与频率限制 |
| AI 识图、生成、重新生成 | 按确认的规则扣点，记活动发起人账户 |
| 手工编辑、版本查看、定稿、导出 | 不扣点 |
| 同一请求重试、查看任务进度、读取缓存 | 不重复扣点 |

### 13.3 建议计价方式

采用用户可理解的固定规则，而非直接按不可预知的 token 数结算：

> 本次预计点数 = 写作档位点数 + 本次未缓存且需要识别的图片数 × 每图识别点数。

篇幅、输入量和模型需有上限，保证规则覆盖可控成本。实际 token 和供应商成本在后台记录，不直接当作用户点数。规则、模型及价格版本在任务确认时锁定，后续调整不影响已有任务。

### 13.4 预扣、结算与退款

1. 用户查看明确报价，确认后服务端检查权限、余额、限流及预算。
2. 以原子操作冻结预计点数并创建唯一任务，冻结成功才可调用 AI。
3. 任务成功落库后结算扣点、释放剩余冻结点数，记账一次。
4. 建议首版采用“未交付完整草稿则全额退还本次冻结点数”，部分阶段成本由平台承担，并通过预算与频控防止反复失败滥用。
5. 调用结果不明时进入待核实，先查询原任务，不能立即重试调用或一边退款一边继续执行。
6. 故障恢复任务核对在途冻结与最终结果，禁止长期悬挂、重复退款或重复扣费。

报价后余额被其他活动使用、素材改变导致报价失效等情况，返回重新确认，不擅自提高扣点。已有缓存无论任务是否退款，后续均按实际是否需要调用计算费用。

## 14. 防滥用与成本控制

- 按用户、活动及必要的来源维度限制创建、上传、识图、生成频率；账号限制以外仍需平台总量保护。
- 同一活动仅一个在途任务，同时设置用户并发与每日点数消费上限。
- 限制文字输入总量、单图大小、图片总量、输出 token、模型超时与重试次数。
- 平台设置每日和每月成本预算，包含写作及图片识别；估算在途成本需先占用预算，不能只统计已完成任务。
- 达到预算后阻止新 AI 调用，保留查看、人工编辑和导出功能。全局开关支持人工紧急暂停。
- 每个微信身份只能领取一次赠点，但这不能阻止多账号套利；结合领取频控、异常行为告警及总预算限制，不宣称可以完全杜绝。
- 重复失败、异常高频、短期大量账号等触发告警，可暂停账号或活动 AI 权限。人工恢复留痕。
- 素材内容作为数据处理，不允许其文本改变系统指令、触发额外工具调用或扩大预算。
- 后端密钥仅在服务端保存；按需配置供应商侧额度限制，作为应用控制之外的额外成本边界。
- 免费上传也有存储和带宽成本，需按用户与活动设容量、文件清理策略及平台存储预警。

## 15. Web 平台管理后台

### 15.1 概览

展示用户数、活动数、任务成功失败数、赠送与消耗点数、模型用量、估算成本、预算余量和异常告警。可按日期筛选，点数消耗与实际供应商成本分开呈现。

### 15.2 用户管理

按用户 ID、姓名、状态查找，重名必须能区分。查看余额、冻结、账本、活动、AI 任务和赠点领取记录；支持暂停 AI 权限或停用账户、恢复、手动调整点数。

调整点数需二次确认并填写原因，显示调整前后余额；提交重试不得重复入账。后台不展示不必要的微信身份原始标识。

### 15.3 活动与任务管理

查看活动归属、成员数、素材量、状态和 AI 消耗；可暂停指定活动的 AI 使用。查询任务各阶段、报价、扣点、退款、缓存命中、模型、token 和错误分类。

需查看活动内容排查问题时按权限提供受控入口并记录访问，不将所有私人资料默认展示在列表。不得通过后台“重试”绕过原有扣点、预算和去重规则。

### 15.4 规则与预算配置

配置新用户赠点、计价规则、输入上限、调用频率、每日额度、平台预算和全局 AI 开关。修改需记录版本、操作者、生效时间及原因，可恢复到旧配置；恢复不改变历史账本。

### 15.5 审计与异常处理

点数调整、用户限制、管理员登录、规则变更、预算开关、历史账户绑定等操作留痕。支持按用户、任务和流水号对账。后台首版只向明确授权的平台管理员开放，不提供任何用户自行注册管理员的入口。

## 17. 异常场景要求

| 场景 | 预期处理 |
|---|---|
| 两人同名 | 独立用户、独立资料与余额 |
| 邀请中途需要登录 | 登录后返回原活动 |
| 发送时断网 | 保留输入，重试不重复发 |
| 上传期间暂停收集 | 停止新增写入，提示并清理孤立文件 |
| 两名管理者同时点生成 | 只创建一个任务，不重复冻结与调用 |
| 余额被其他活动占用 | 提示不足，不发起 AI |
| 前端超时但后台仍执行 | 继续查询原任务，不自动创建新任务 |
| AI 成功但文章保存失败 | 进入恢复流程，优先复用结果，不重新调用；按最终交付结果结算 |
| 生成期间资料变化 | 保留快照结果，标记待核对 |
| 生成期间协作者权限撤销 | 阻止新任务，已获授权的在途任务继续受预算约束并可追溯 |
| 平台达到预算 | 停止新的供应商调用；未开始任务按规则取消退款 |
| 成员被移除 | 停止访问和提交，历史资料保留供管理者处理 |
| 点数调整重复提交 | 只记一笔，返回原结果 |

## 18. 非功能要求

- 所有核心页面提供加载、空状态、失败重试和权限不足状态。
- 素材流分页加载，图片使用缩略图和懒加载；文件上传与 AI 任务不阻塞页面基本操作。
- AI 任务持久化，应用重启可恢复查询与对账；日志关联用户、活动、任务和流水号。
- 日期按用户使用场景显示，后台默认北京时间；数据库记录统一时间标准。
- 数据备份和恢复方案覆盖身份、角色、文章版本、账户及流水。
- 对已登录未授权、被移除成员、停用用户、普通后台用户分别执行访问测试。
- 按真实数据流更新隐私说明，包括显示姓名、用户提交图片文字以及向 AI 服务发送的必要内容；不因取消微信昵称授权而宣称未处理任何用户资料。
- 上线前验证公众号复制后的图片、标题与排版，不能仅以网页预览正常作为验收通过。

## 19. 验收标准

1. 两个相同姓名的微信用户互不串号；同一微信再次进入恢复原身份；输入管理员姓名不能获得权限。
2. 每个活动独立授权，普通成员不能通过直接请求执行管理或 AI 操作。
3. 从邀请进入的新用户登记后进入指定活动；归档、失效邀请、移除成员行为符合规则。
4. 可以发送纯文字、多图和多图说明；断网重试不重复，自己的资料可以撤回，不能撤回他人资料。
5. 不存在回复、评论、录音等本次范围外入口。
6. 无人工选择也可生成；指定排除不进入生成；指定采用被纳入，超限时明确阻止。
7. 活动事实进入提示，图片经过实际理解或缓存复用；仅图片、事实不足时不凭空编造活动信息。
8. 生成不关闭收集，暂停可恢复，新增或撤回资料能触发文章变更提醒。
9. 草稿可修改，重新生成保留旧版本，定稿和人工标记发布相互区分，导出内容可在公众号编辑器核验。
10. 新用户赠点只发一次；迁移和重复登录不能重复领取；余额与账本一致。
11. 未冻结点数不调用供应商；重复请求、并发和任务重试不重复扣点或调用；失败退款可核对。
12. 协作者只有获得消费授权才能使用发起人点数，余额不足不影响资料查看、手工编辑和导出。
13. 每日限额、并发限制、全局预算和暂停开关在服务端有效，达到阈值能阻止新调用。
14. 平台后台可手动增减点数、查流水、停用和恢复用户、调整规则，全部留审计记录。
15. 普通用户不能进入平台后台；组织者 Web 工作台只能访问授权活动。
16. 旧用户与旧文章迁移经过核对，旧公开预览入口和旧管理员权限不形成绕过路径。

## 20. 实施顺序与本期边界

### 20.1 实施顺序

1. 身份、会话、活动角色和旧数据迁移方案。

### 20.2 不在本期范围

在线支付、点数购买和转赠；聊天回复、私聊、语音视频通话；微信群消息自动同步；公众号自动发布；完整团队组织架构；复杂多人实时协同编辑；面向用户的自定义模型或 API 密钥配置。
