# 班级共创界面重设计验收

## 运行检查

- 在项目根目录运行 `node scripts/frontend.test.cjs`：模拟微信 Page 和 wx API，验证失败草稿保留、提交锁、图片上传复用、主题筛选、成员请求竞态与文章复制链接。需要已安装 backend 依赖。
- 在 backend 目录运行 `npm run build`：Next.js 生产编译与类型检查。
- 小程序使用微信开发者工具打开 miniprogram 目录。五个页面和三个公共组件已通过本机开发者工具内置 WXML 编译器，所有 WXSS 已通过内置样式编译器。

## 已完成验证

- 10 项模拟页面交互回归通过。
- TypeScript 无增量类型检查及 Next.js 生产构建通过。
- 网页使用本地固定数据在浏览器检查 320、375、430、1024px 宽度，无横向溢出。
- 模拟 Clipboard API 成功和拒绝，验证 HTML 复制与手动选择回退只包含文章标题与正文。
- 验证网页文章不存在和读取失败的独立提示。
- 没有使用真实账号提交素材、调用付费生成，或进行线上部署。

## 真机验收

1. 根据环境配置 miniprogram/app.js 的 globalData.baseUrl；文章预览链接也从此地址生成。手机不能使用电脑的 localhost，测试需配置可访问的后端地址。
2. 微信后台配置服务器、上传和图片下载域名；补齐涉及相册、相机和剪贴板能力的隐私声明。前端已移除开发阶段自动同意隐私的逻辑，使用原生授权流程。
3. 分别使用成员与管理员，走通登录、加入主题、发送500字文字、相册/拍照选图、生成文章、预览、复制流程。普通成员在“我的”看到个人信息，不显示管理区。
4. 检查 iOS/Android 权限拒绝、取消选图、图片超过10MB、不支持格式、上传失败、上传成功但素材保存失败，以及连续点击。一次最多选6张，逐张上传；部分失败保留待重试图片，成功上传但保存失败的图片复用地址。
5. 检查小屏、大字号、长主题名称和带底部安全区设备；展开输入框并弹起键盘，确认发送按钮与最后一条素材不被遮挡。
6. 在微信公众号编辑器实际粘贴富文本并核对图片、标题、段落与排版。浏览器测试模拟了剪贴板，不代表公众号粘贴结果已验收。

## 实现约定

- 沿用原始接口、角色模型和数据库结构；本轮没有新增语音服务。
- 录音入口已收起，历史语音素材显示不可播放提示。
- 本地图标的 SVG 作为源文件保留，界面和原生 tabBar 使用 PNG。
- 生成文章使用已有同步请求，只展示真实等待状态，不展示百分比。
- 当前主题成员以选择的主题为准，请求返回时校验请求序号，避免旧响应覆盖新选择。
