# AI 自由排版：2.5.0 本地开发与验证

状态：本地功能完成，未部署后端，未开启线上动态计费，未提交微信审核。不能用小程序预览码单独证明线上 AI 排版可用。

## 用户流程

文章共创 → 活动 → 文章 → AI 美化整篇 → 可选填写设计要求 → 查看预计点数及最高冻结 → 确认排版 → 查看新版本。已有设计可点击“换一种设计”，新请求单独报价、单独计费。历史版本可恢复，成员及公开分享页使用保存的设计。

固定风格选择器已从文章页和分享网页移除。未排版的旧文章只做基础阅读排版；AI 根据正文气质、设计要求、图片说明/关联文字与已有识图缓存，自主生成 HTML 与内联样式。不会额外调用识图或猜测未识别的画面。每张图是否加框、是否使用原始图注、大小和位置均由 AI 决定；不要求套用开场框、章节块或结束卡。

## 原文保护与 HTML

模型读取完整正文，但输出 HTML 时引用 title/p1/p2 等原文占位符，以及 asset:img1 等图片引用。系统严格检查段落按顺序各出现一次、图片各出现一次，再填入经过转义的原文。图注只能引用已有说明，可省略。这样减少全文重复输出 token，也避免设计步骤改写事实。额外叙事文字不允许，装饰符号允许。

使用 htmlparser2 解析成树后重新序列化限定元素与 CSS 属性。脚本、SVG、外链、背景图片、事件属性、定位、隐藏样式等不能直接进入输出。限制树深度/节点数、字号、宽度与边距；具体颜色、留白、字体、边框和组合没有预设主题。图片地址在阅读时绑定有效签名，不把短时签名保存进设计。

排版保存为新的草稿版本，原文与历史设计保留；修改文章正文/标题/图片后清除旧设计，避免显示过期内容。恢复历史版本会恢复其设计。生成期间若文章被修改，排版任务失败退款，人工修改不会被覆盖。

## 任务与扣点

复用现有带租约、冻结、幂等结算的任务队列，以 kind=layout 区分。写作和排版是两笔独立确认的任务，不会生成正文后静默追加付费排版。排版要求管理员先开启动态计费；不自动改变线上计价规则。

排版输出上限单独配置 layoutMaxOutput（默认12000，支持2000–20000），不会沿用纯文本4000上限。单次排版调用超时180秒；响应不确定时转待核实，不自动重复收费调用。格式/原文完整性校验失败则退款，已消耗的供应商 token 记录为平台成本。返回实际用量后按报价时锁定规则结算，退回差额，不额外扣超过用户确认上限的点数。

## 仍需上线前核验

真实手机 rich-text 的字体/边距表现、公众号编辑器粘贴后的兼容性，以及真实长文的设计质量、token分布与延迟。当前兼容范围内的 HTML 不保证三端逐像素一致。不承诺每次设计都与历史完全不同；重新设计会提供前次设计说明和独立设计标识，仍由模型判断。

## 用户视觉反馈后的改进

用户指出最初样例基本没有美化。本轮要求模型先输出针对文章的 designPlan 再生成 HTML，加强标题构图、视觉焦点和局部装饰，而不固定模板组合。新增原文短语摘录占位符，可用于眉题/小节标签/强调摘要；摘句必须来自原文且不可重复。增加安全的双色渐变、简单阴影、圆角百分比和居中边距支持，避免兼容过滤误删装饰。

重新真实调用模型得到观察册风格样例，输入868、输出1061、合计1929 token。已在390px宽度截图复核，无横向溢出；新样例为 device-test/ai-layout/decorated-sample.html，截图 decorated-mobile.png。模型没有给配图加框或生成额外图注。仍未部署线上。

## 后续用户约束：正文设计与标题分离

用户明确图片是否加框应由 AI 的设计判断决定，不预置有框/无框，也不靠增加装饰数量判定审美。提示词已去掉这些方向性偏置。

文章标题仅作为理解主题的元数据，页面普通显示在正文之外；AI HTML 禁止标题占位符及 h1，正文复制容器只包含正文。正文摘句只允许来自正文，不从标题抽取。新布局标记 bodyOnly=true，早期包含装饰标题的实验布局不会直接用于正文导出，需重新生成；未排版正文使用基础阅读样式。新增覆盖测试验证标题不进入复制正文。

更换设计模型仍待同文效果比较与服务配置，未声称当前模型审美已达到用户预期，也未切换付费服务。

## 沿用现有模型

用户明确继续使用现有模型，不切换供应商。排版要求改为由模型判断文章的层次、留白、图文与装饰关系，不规定有框/无框、不强制装饰清单或固定风格。真实模型复核通过：输入829、输出844、合计1673 token，标题未进入正文；样例 body-only-sample.html。审美效果仍以用户验收为准。
