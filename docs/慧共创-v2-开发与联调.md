## 本轮实现

UI 已确认，“我的活动”统一改为“共创活动”。正式入口为 `miniprogram/pages/co-create/index`，微信原生页面调用 `/api/v2/…`。旧页面源码保留以便对照，但不再注册为入口。创建/编辑活动只有名称和选填说明，没有额外封面、分类、地点、时间或标签字段。

- 微信 code 换身份，服务端会话、过期、退出、停用与姓名修改；姓名不参与账号识别。
- 活动角色独立，协作者 AI 授权单独控制；成员移除后禁止通过原邀请自行重返。
- 邀请码、微信分享卡片、微信二维码、登录后返回邀请、暂停/归档状态。
- 私有图片签名直传，确认发送后上传；图片与说明关联提交，失败保留，复用已上传对象与幂等请求标识。
- 文字/图片资料流、分页历史、新资料提示、个人撤回；人工选材、批量选材与两种生成方式。
- 锁定报价与资料快照，原子预扣与预算预占；持久任务、分批识图、写作、结算、退款、待核实与后台对账。图片缓存按活动与模型隔离，排除资料不进入快照。
- 标题/正文/图片说明与顺序编辑；保存新版本、冲突检测、版本恢复、采用清单、素材变化提醒、人工定稿。生成与定稿不关闭活动收集。
- 成员可见与公开分享分别控制，公开文章 `/s/{token}`；链接可撤销，可在电脑复制富文本至公众号后台，人工标记发布。
- `/manage` 独立管理员登录，用户点数、停用/恢复、任务、预算/计价配置、审计、历史账号核验绑定。点数调整要求原因、余额核对、二次确认并去重。
- 旧 `/api/auth`、`/api/generate` 等接口返回升级提示；旧 `/view/{topicId}` 不再返回文章内容。

## 需要完成的环境配置

现有 `.env.local` 中只有旧 Supabase 与 DeepSeek 配置。本轮没有打印、替换或提交其中的密钥。

按 `backend/.env.example` 补齐：微信 AppID/AppSecret，稳定且不少于 32 字符的 AUTH_SECRET，独立 CRON_SECRET，平台管理员账号与 scrypt 密码哈希，兼容 `image_url` 输入的识图 API 地址/模型/密钥。写作默认沿用 DeepSeek。

`AUTH_SECRET` 同时用于微信身份的 HMAC 关联，不能随意轮换；先备份并制定重新关联方案。管理员不是首个用户，也不继承旧管理员身份。`scripts/hash-admin-password.cjs` 从标准输入读取密码并生成哈希，避免把密码写进命令行参数。

小程序配置 request/downloadFile 域名：后端域名与 Supabase 域名；图片通过 wx.request PUT 直传 Supabase，需将 Supabase 域名加入 request 合法域名。按真实数据流配置微信隐私保护指引。二维码在对应 release/trial/develop 版本存在后才能生成。

## 数据库迁移与旧账号

1. 备份旧 User/Topic/Member/Material/Article 与 Storage；新版上线窗口暂停旧写入。
2. 在 Supabase SQL Editor 先执行 `backend/prisma/hui-v2-prepare.sql`，仅新增 `hui_state`、CAS RPC 与私有 `hui-materials` 桶，不修改旧表和旧图片桶。完成备份及新版联调，正式切换时再执行 `backend/prisma/hui-v2-cutover.sql`，关闭旧数据匿名访问、将旧 `materials` 桶设为私有。原 `hui-v2.sql` 已改为防误执行提示。
3. 普通微信用户先登录新系统获得稳定用户 ID。
4. 在平台后台“历史账号认领”核对本人后绑定旧 ID 与新用户 ID。会导入关联活动、成员、素材和文章；旧全局管理员不继承平台权限，同名不自动绑定。未核验历史成员保留占位信息，无访问身份。迁移账户不会再发一次赠点。
5. 历史文章按待核对草稿导入。发起人核对后重置邀请、定稿并重新分享；旧的 ID 公开文章链接停止访问。

当前迁移工具针对小规模旧库：任一旧表超过 1000 行或单账户关联图片超过 100 张时会明确阻止，必须先扩充分批迁移工具，不会静默截断。绑定过程中图片采用确定性目标路径，可在失败后重试；同一账号完成绑定后不重复绑定。

## 事务与运行边界

首版小团队使用 PostgreSQL 单行 JSONB 聚合数据与 compare-and-swap 事务。所有点数、幂等记录、版本和任务冻结在同一次 CAS 中提交，冲突重新读取重算；生产环境无内存、文件或演示数据兜底。服务角色密钥只在后端使用，匿名和普通数据库用户无聚合数据访问权限。

该方案优先保证本轮小团队业务的事务一致性，数据库每次写入整个聚合对象；规模扩大前需要拆分规范化表与账务 RPC，并迁移审计/请求记录，不能视为大规模并发架构。2026-11-06 已执行第一阶段初始化，真实 RPC 读写和匿名拒绝检查通过；第二阶段旧版权限切换尚未执行。

任务单次 worker 最多实际识图 2 张，再释放为排队状态，由客户端或 cron 继续接力，避免大量图片阻塞单个函数。写作前使用已完成的活动内识图缓存。worker 执行权跨实例互斥；超过执行租期未确认的供应商操作转待核实，不自动二次调用。网络结果不明时保留冻结，管理员核实后退款或恢复已保存的结果。

`backend/vercel.json` 配置每分钟 worker，部署前确认宿主计划支持该频次并设置 CRON_SECRET。也可使用外部调度器或本地运行：

```sh
node --env-file=backend/.env.local scripts/v2-worker.mjs
```

配置初始 AI 关闭、赠点与预算为 0。平台管理员先确认点数规则、输入上限、供应商 token 单价、单图成本上限、单任务成本预占上限及日/月预算，再开启 AI。任务预占使用输入字节上限、输出上限和图片保守成本估算；后台同时保存供应商返回的 token 与按锁定单价计算的成本。保守预算占用和实际用量成本分别呈现，供应商未返回完整用量时标为待核对。供应商侧也应设置额度边界。

过期未提交图片由 worker 清理。已撤回图片和文章历史引用保留；正式存储保留期仍需在上线前确认，当前不会自动删除历史版本引用文件。

## 最新确认的运行规则

- 复用小程序项目中的 AppID；AppSecret 已补齐，微信 stable_token 凭证验证通过；现有 AppID 保持不变。
- 本地管理员账号为 `admin`，随机密码存于 `backend/admin-credentials.local`（文件权限 600，已被 Git 忽略）；后端仅配置 scrypt 哈希。AUTH_SECRET 与 CRON_SECRET 已在本地生成，之后部署需沿用稳定值。
- 新用户仅赠送一次 12 点，每次写作 5 点；仅对新注册账号生效，不自动改写已有余额和账本。
- 每日平台 AI 成本预算 500 分（5 元），按北京时间并计入所有在途预占；跨日任务也占用当日预算。月预算暂不另外限制，0 表示只执行每日上限。
- 图片识别关闭，上传与文章配图保留。图片不产生识图调用、无需识图密钥、不收取识图点数；AI 仅参考文字与活动说明，不得声称识别了照片内容。仅图片且缺乏说明时，要求补充文字。
- 核对 [DeepSeek 官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)后，写作继续复用现有 DeepSeek Key，使用当前文档中的 `deepseek-flash`；固定非思考模式和 JSON 输出。预算按未命中输入高峰 2 元/百万 token、输出高峰 8 元/百万 token 的保守单价预占，未进行付费调用。该成本单价与用户每次 5 点分别管理。

以上已写入本地配置与新安装默认规则；2026-11-06 第一阶段初始化完成，规则已持久化至新表，线上旧版权限和图片桶未改动。已有 v2 配置实例需在迁移完成后导入 `backend/config/launch-policy.json` 对应规则，保留原账本；写作服务开关继续保持关闭，待真实环境就绪再开启。
